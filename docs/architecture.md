# Architecture

metron receives the OpenTelemetry spans an agent sends, stores them in a local SQLite file, and lists what was recorded from the terminal.

## Components

| Package | Role |
|---|---|
| `cmd` | The root command (`--db`, `--version`) and its subcommands, one package each: `serve` (`--tag`, `--listen`, `--port`, `--grpc-port`), `ls` (`--limit`, `--tag`, `--sessions`), `show` (`[tag or session]`) and `compare` (`<a> <b>`) |
| `cmd/internal/session` | Finds and opens the database for the read commands without creating it |
| `internal/store` | Opens SQLite, applies settings, runs migrations, exposes typed queries |
| `internal/store/db` | Code generated by sqlc |
| `internal/compare` | Summarizes two sets of traces into side-by-side metrics |
| `internal/normalize` | Reads kind, model and token counts from a span's GenAI attributes |
| `internal/receiver` | Accepts OTLP trace exports over HTTP and gRPC on the addresses it is given and saves them as spans |
| `internal/receiver/spans` | Converts an OTLP export into span rows |
| `internal/render/sessions` | Sessions and groups tables |
| `internal/render/timeline` | Span timeline |
| `internal/render/comparison` | Comparison table |
| `internal/render/listener` | Listener status lines |
| `internal/render/internal/ui` | Color styles, table layout and formatting shared by the views |

## Stack

| Concern | Choice |
|---|---|
| Language | Go |
| CLI | `spf13/cobra` |
| SQLite driver | `modernc.org/sqlite` (pure Go, no cgo) |
| Migrations | `pressly/goose`, embedded in the binary |
| Queries | `sqlc` generates typed Go from SQL |
| Terminal output | `charmbracelet/lipgloss` table |
| OTLP | `go.opentelemetry.io/proto/otlp`, `google.golang.org/grpc`, `google.golang.org/protobuf`, stdlib `net/http` |

## Storage

One file per project at `.metron/metron.db`, relative to the working directory.

Connection settings: WAL journal, `busy_timeout=5000`, foreign keys on.

```
sessions  id, tag, start_time, end_time
spans     trace_id, span_id, parent_span_id, session_id → sessions.id,
          name, kind, status, start_time, end_time,
          model, input_tokens, output_tokens, attributes (JSON)
```

A session is one `metron serve` run and carries the tag. One with no `end_time` is shown as running, otherwise done. Several sessions can share a tag; each keeps its own row, ID and times.

Spans are stored with IDs as hex, status as `unset` / `ok` / `error`, and `attributes` as `{"span": {...}, "resource": {...}}`, which keeps every attribute the app sent. `kind`, `model` and the token counts are read out of those attributes when the span arrives. `show` reads them back.

## Normalizing

`normalize.Span` fills the columns from the OpenTelemetry GenAI attributes, in this order:

| Column | Reads |
|---|---|
| `kind` | `tool` if `gen_ai.operation.name` is `execute_tool` or `gen_ai.tool.name` is set; `other` for `invoke_agent` and `create_agent`; `model` if a model attribute is set or the operation is `chat`, `text_completion`, `generate_content` or `embeddings`; otherwise `other` |
| `model` | `gen_ai.request.model`, then `gen_ai.response.model` |
| `input_tokens` | `gen_ai.usage.input_tokens`, then `gen_ai.usage.prompt_tokens` |
| `output_tokens` | `gen_ai.usage.output_tokens`, then `gen_ai.usage.completion_tokens` |

A missing or unusable value (negative, fractional, not a number) is stored as NULL. Token counts sent as floats or numeric strings are accepted. `status` is not changed: `unset` means the app did not mark the span as failed.

Spans stored before a column was filled keep their old values.

## Listening

`metron serve [--tag T] [--listen ADDR] [--port N] [--grpc-port N]`:

1. Opens (or creates) the database and inserts a `sessions` row with a random 12-character hex ID and the tag.
2. Starts the receiver on `127.0.0.1:4318` (HTTP) and `127.0.0.1:4317` (gRPC), the OTLP defaults, so an exporter needs no endpoint setting.
3. Saves each batch of spans as it arrives, linked to the session. Nothing is started or supervised; metron only receives.
4. On Ctrl+C or SIGTERM, shuts the receiver down (waiting up to 5s for in-flight exports), records the end time and prints the span count to stderr.

If a port cannot be bound, the session row is deleted and the error names the flags to change it.

## Reading

A tag names a group of sessions. Commands treat every session sharing a tag as one, and an untagged session as a group of its own.

`metron ls` lists groups, newest first: one row per tag with its session count, trace count, earliest start, latest span activity and status (running while any of its sessions is running), and one row per untagged session. `--sessions` lists every session row instead, with its own ID, start, duration and status. `--tag` filters either view.

`metron show [tag or session]` prints a timeline:

1. Resolves the argument as a tag first, which selects every session with it, then as a session ID prefix, which selects one session. With no argument it takes the group of the most recently started session. A name that matches nothing, or an ID prefix that matches more than one session, is an error.
2. Merges the spans of the selected sessions ordered by start time and groups them by `trace_id`, traces in the order they first appear.
3. Prints a header, then for each trace a line with its duration, span count and error count, then one row per span: offset from the trace start, kind, name, model, duration, tokens and error mark.

Like `ls`, it never creates the database.

`metron compare <a> <b>` puts two groups side by side:

1. Resolves each argument like `show`: a tag selects every session with it, otherwise a session ID prefix selects one. A side with no traces is an error.
2. Reduces each side to one row per trace: duration from its first span start to its last span end, error spans, model and tool calls, and input and output tokens summed over its model spans. A trace split between two sessions is merged.
3. Prints one row per metric with the value for each side and the change from the first to the second: trace count, mean and median duration, share of traces with an error, model and tool calls per trace, and input and output tokens per trace.

Changes in duration, errors and tokens are green when they fall and red when they rise; the others are not judged. The trace count shows no change, since it is a sample size and not a result.

## Decisions

- **Local SQLite instead of a server.** No setup, one file, queryable with plain SQL.
- **Pure-Go driver.** Keeps the binary free of C dependencies.
- **Migrations embedded in the binary.** The database is created and upgraded on first open; there is no init command.
- **sqlc instead of an ORM.** Queries stay plain SQL and results are typed.
- **`ls` never creates the database.** Running it in the wrong folder leaves nothing behind.
- **Plain output when piped.** lipgloss detects the terminal, so redirected output has no color codes.
- **One port for HTTP and gRPC.** The receiver serves HTTP/1.1 and unencrypted HTTP/2 and routes gRPC requests by content type, so one endpoint works whichever protocol the exporter uses.
- **Standard OTLP ports.** `serve` listens on 4318 and 4317 so an app that only emits OpenTelemetry reaches it with no configuration.
- **Loopback by default.** The listener has no authentication; `--listen 0.0.0.0` is needed for an agent in a container and exposes it to the network.
- **A tag groups sessions.** Every span received while `serve` runs carries its tag; to compare versions, stop and start `serve` with another tag. Starting `serve` with a tag that already exists adds a session to that tag and never reopens a finished one.
- **Only standard attribute names.** Normalize reads the OpenTelemetry GenAI conventions and nothing app-specific, so any app that follows them works.
- **Normalized at ingest.** Each span is complete when stored, so a running session can be read and a session that never ends cleanly loses nothing.
- **No cost column.** Cost can be derived from model and token counts when it is needed, so nothing stores it.
- **Timeline, not a tree.** `show` orders spans by start time and ignores `parent_span_id`, so it reads the same for an app that links its spans correctly and one that hangs them all off the root.
- **Tokens come from model spans.** Summing every span would count tokens twice for an app that also reports usage on its agent span.
- **Duplicate spans ignored.** Exporters retry failed batches, so a span already stored is skipped.
- **Write failures return 503 / `Unavailable`.** Those are the codes OTLP exporters retry.
- **Hex IDs in OTLP/JSON.** JSON exports carry trace and span IDs as hex, which are converted before decoding.
