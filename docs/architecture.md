# Architecture

metron runs an agent command, records the run and the OpenTelemetry spans the agent sends in a local SQLite file, and lists runs from the terminal.

## Components

| Package | Role |
|---|---|
| `cmd` | Cobra commands: root (`--db`, `--version`), `run` (`--tag`, `--case`) and `ls` (`--limit`, `--tag`) |
| `internal/store` | Opens SQLite, applies settings, runs migrations, exposes typed queries |
| `internal/store/db` | Code generated by sqlc |
| `internal/runner` | Starts the agent command, forwards signals, reports its exit code |
| `internal/receiver` | Accepts OTLP trace exports over HTTP and gRPC on one local port and saves them as spans |
| `internal/render` | Runs table, run summary line, shared formatting, color styles |

## Stack

| Concern | Choice |
|---|---|
| Language | Go |
| CLI | `spf13/cobra` |
| SQLite driver | `modernc.org/sqlite` (pure Go, no cgo) |
| Migrations | `pressly/goose`, embedded in the binary |
| Queries | `sqlc` generates typed Go from SQL |
| Terminal output | `charmbracelet/lipgloss` table |
| OTLP | `go.opentelemetry.io/proto/otlp`, `google.golang.org/grpc`, `google.golang.org/protobuf`, stdlib `net/http` |

## Storage

One file per project at `.metron/metron.db`, relative to the working directory.

Connection settings: WAL journal, `busy_timeout=5000`, foreign keys on.

```
runs   id, tag, case_name, command, start_time, end_time, exit_code
spans  trace_id, span_id, parent_span_id, run_id → runs.id,
       name, kind, status, start_time, end_time,
       model, input_tokens, output_tokens, cost_usd, attributes (JSON)
```

A run with no `end_time` is shown as running.

Spans are stored raw: IDs as hex, status as `unset` / `ok` / `error`, and `attributes` as `{"span": {...}, "resource": {...}}`. `kind`, `model`, tokens and cost are not filled in yet. Nothing reads `spans` yet.

## Recording a run

`metron run [--tag T] [--case C] -- <command>`:

1. Opens (or creates) the database and inserts a `runs` row with a random 12-character hex ID.
2. Starts a receiver on a random port on `127.0.0.1`.
3. Starts the command with metron's environment, stdin, stdout and stderr, plus `OTEL_EXPORTER_OTLP_ENDPOINT` pointing at the receiver.
4. Saves each batch of spans the agent exports as it arrives, linked to the run.
5. When the command exits, shuts the receiver down (waiting up to 5s for in-flight exports) and records the end time and exit code.
6. Prints a one-line summary with the span count to stderr and exits with the command's exit code.

Exit codes: the command's own code; `128 + signal` if it was killed by a signal; `127` if it could not be started.

## Decisions

- **Local SQLite instead of a server.** No setup, one file, queryable with plain SQL.
- **Pure-Go driver.** Keeps the binary free of C dependencies.
- **Migrations embedded in the binary.** The database is created and upgraded on first open; there is no init command.
- **sqlc instead of an ORM.** Queries stay plain SQL and results are typed.
- **`ls` never creates the database.** Running it in the wrong folder leaves nothing behind.
- **Plain output when piped.** lipgloss detects the terminal, so redirected output has no color codes.
- **Exit with the agent's exit code.** Scripts and CI see the real result; `cmd.ExitError` carries the code to `main`.
- **Ctrl+C is not forwarded.** The terminal already sends it to the agent; metron stays alive so it can record the end. SIGTERM and SIGHUP are forwarded, since they usually reach only metron.
- **Summary on stderr.** The agent's stdout stays clean for piping.
- **Flags stop at the command.** `metron run python agent.py --verbose` passes `--verbose` to the agent; `--` is optional.
- **One port for HTTP and gRPC.** The receiver serves HTTP/1.1 and unencrypted HTTP/2 and routes gRPC requests by content type, so one endpoint works whichever protocol the exporter uses.
- **One receiver per run.** Every span it receives belongs to that run, so the run ID comes from the receiver rather than from span attributes.
- **Random port.** Avoids clashing with other collectors on 4317/4318.
- **Overrides the agent's endpoint.** `OTEL_EXPORTER_OTLP_ENDPOINT` is replaced and `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` removed, since the latter would take precedence.
- **Duplicate spans ignored.** Exporters retry failed batches, so a span already stored is skipped.
- **Write failures return 503 / `Unavailable`.** Those are the codes OTLP exporters retry.
- **Hex IDs in OTLP/JSON.** JSON exports carry trace and span IDs as hex, which are converted before decoding.
